Your transactions, your server.

FinanceKitSync copies your Apple Card, Apple Cash, and Apple Pay transaction history to a machine you control. No account. No backend of ours. Nothing in the middle.

Source on GitHub Run the server

How it works

Your iPhone FinanceKit reads your history
→
Encrypted POST TLS, bearer token
→
Your server SQLite you own

The app asks iOS for permission to read financial data, walks your entire transaction history, and sends anything your server hasn't already acknowledged. It keeps a small local record of what it has delivered, so a second sync sends only what changed — and a corrected amount or a pending → posted flip counts as a change.

That's the whole app. It doesn't categorize, budget, chart, or advise. It moves your data to where you can do those things yourself.

What stays on your phone

Only bookkeeping. For each transaction already delivered, the app stores an identifier, a SHA-256 checksum used to notice corrections, and a timestamp. No amounts. No merchants. If someone dumped that database, they'd learn how many transactions you have and nothing else.

What we receive

Nothing. There is no “we”. There is no server to receive it.

Running a server

You need somewhere for the data to land. The receiver is about 200 lines of Python — FastAPI in front of a SQLite file — and runs anywhere Docker does: a VPS, a home server, a Raspberry Pi, a spare laptop. 

git clone https://github.com/AndrewSB/FinanceKitSync
cd FinanceKitSync/server

# Generate a token and start it
printf 'FKS_TOKEN=%s\n' "$(openssl rand -hex 20)" > .env
mkdir -p data && chown -R 10001:10001 data
docker compose up -d --build

curl http://127.0.0.1:8501/health
# {"status":"ok","schema_version":1}

Then put it behind HTTPS — the app refuses plain http://. Any reverse proxy with a real certificate works. If you'd rather not open a port or manage DNS, Tailscale Funnel does both in one command: 

tailscale funnel --bg --https=8443 http://127.0.0.1:8501
Funnel is per-port, not per-path. Enabling it publishes every route already served on that port, and turning it back off deletes the port's whole configuration. Check tailscale serve status before you enable it, and pick a port nothing else is using.

Enter the resulting URL and your token in the app under Connect your server, tap Test connection, and you're done.

Honest limitations

  • You need to run a server. There's no hosted option, and there won't be.
  • Only what FinanceKit exposes — Apple Card, Apple Cash, and Apple Pay. Not your other banks.
  • Background syncs happen when iOS decides, not on a schedule. Open the app and pull to refresh when you want it now.
  • iPhone only. FinanceKit doesn't exist on Mac, iPad, or Android.
  • Your server holds your complete transaction history. Securing and backing it up is on you.

Questions

Can you see my transactions?

No, and not as a policy promise — as an architectural fact. The app has exactly one network destination: the URL you type in. There are no analytics, no crash reporting, and no third-party SDKs. You can verify this; the source is public.

What if my server is down?

Nothing is lost. The app only marks a transaction as delivered after your server confirms it, so anything unacknowledged is retried on the next sync. A server that's offline for a week catches up in one run.

What if I rebuild my server and lose the database?

Use Re-send everything in Settings. It clears the local delivery record so the next sync replays your full history. The server stores transactions keyed on their identifier and updates in place, so replays never create duplicates.

How far back does it go?

As far as FinanceKit does — typically your whole history with the account. The first sync sends all of it, which can be thousands of transactions; after that it's just what changed.

Is this related to LunchSync?

Yes. This started as an optional feature inside LunchSync, which syncs the same data to Lunch Money specifically. It was split out, with that project's owner's agreement, because “send it to one budgeting service” and “send it wherever I want” are different products.
